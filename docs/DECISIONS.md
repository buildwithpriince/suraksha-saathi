# Decisions Log

Format: `D-XXX — Title (date) — Decision. Why. Alternatives rejected.` Append only; supersede, don't edit.

- **D-001 — Unity + AR Foundation for the app.** PS requires an APK with AR overlaid on real surroundings; needs ARCore plane detection and image tracking. WebAR rejected (no reliable plane AR on low-end Android, not an APK). React Native AR rejected (thin ecosystem, risky under time pressure).
- **D-002 — UI Toolkit with Advanced Text Generator, not TextMeshPro.** TMP does not shape Devanagari conjuncts/matras correctly; ATG uses HarfBuzz/ICU. Hindi and Santali are judged requirements.
- **D-003 — Scenario steps are data.** One generic ScenarioPlayer + JSON content lets us add modules without code, keeps safety content reviewable by non-programmers, and lets the engine be unit-tested.
- **D-004 — Local storage: SQLite.** Needed for transactional outbox. Candidate package: `gilzoide/unity-sqlite-net` (UPM, Android support). Fallback if it blocks us for > 2 hours: JSON files with atomic write + in-memory outbox index. Confirm in T-40 and record the outcome here.
- **D-005 — Two-level signature chain (root -> device attestation -> certificate).** Enables issuance AND verification with no network, which is a promised differentiator. Plain signed URL rejected (fails offline). Blockchain rejected (unnecessary; judges may see it as a buzzword).
- **D-006 — JWS-style compact tokens; verify over transmitted bytes.** Avoids cross-language JSON canonicalization bugs between C#, Python and TypeScript.
- **D-007 — Core C# tested with `dotnet test` outside Unity.** Fast feedback loop for Claude Code; Unity batchmode tests are slow and blocked when the Editor is open.
- **D-008 — Backend: FastAPI + Supabase Postgres on Render; dashboard on Vercel.** Matches team experience and the PPT.
- **D-009 — Generated content copy is not committed (2026-09-18).** `app-unity/Assets/StreamingAssets/content/` is gitignored; an Editor script (T-08) copies `/content` in on import and before every build. Keeps `/content` the single source of truth, so an APK can't ship stale scenarios. Committing the copy rejected (drifts silently whenever someone forgets to re-import).
- **D-010 — LF line endings everywhere; binaries in Git LFS except under `dashboard/` (2026-09-18).** `.gitattributes` sets `* text=auto eol=lf` (only `.bat`/`.cmd` are CRLF), so Windows clones (`core.autocrlf=true` by default) and macOS clones are byte-identical: Unity YAML stays LF for Smart Merge, and scenario JSON, string CSVs and `content/trust/*` read the same everywhere. Dashboard binaries stay in plain git because Vercel skips LFS files unless enabled per project. Relying on each teammate's `autocrlf` rejected (differs per machine).
- **D-011 — Health check is liveness only (2026-09-18).** `GET /v1/health` returns `{"status":"ok"}` without touching the database; it is Render's health-check path. A database outage then doesn't mark a working web process unhealthy, and tests don't need Postgres just to check the app is up. DB check in the same route rejected (couples liveness to Supabase; add a separate readiness check if needed). Unversioned `/healthz` rejected (docs/06 base path is `/v1`).
- **D-012 — Generic error codes come from the HTTP status (2026-09-18).** The app factory turns every error (404, 405, 422, unhandled 500s) into the docs/06 envelope, with the code list in docs/06; endpoints raise `ApiError(status, code, message)` for specific codes. 500s never include details. Unity sync client and dashboard see one error shape from the first endpoint on. Keeping FastAPI's default `{"detail": ...}` until T-51 rejected (clients would code against two shapes).
